# Обновление и выпуск HWMP

[English — основной документ](../UPDATE_WORKFLOW.md)

1. Прочитать AGENTS, NEXT_SESSION, список полевых испытаний и профильный отчёт. Записать commit/fix/SHA всех BIG; сохранить предыдущий пакет за пределами игры. Не менять потребителей автоматически.
2. Подготовить собственные игру, Toolkit и именно Test21: SHA f12e17bf9c6849599afaefa4d8281c266d637cdfc992a117ec3165891cd58f41. `python tools/prepare_inputs.py` проверяет donor inventory и родные данные. `--economy` нужен для исторических сравнений Classic/обычного2.3. Настройки и ассеты в Git не идут.
3. Править первоисточник: generator/templates для генерируемых overrides, transport.lua для перевозки, production_data.py для справочника, localization/hwmp24.json для новых подписей. Правка только готового generated файла будет перезаписана. Сохранять авторов и неизменённые настройки оружия.
4. `python tools/hwmp24.py`, затем verify_hwmp24.py, verify_effect_journal.py и verify_installation.py. Не запускать Python с `-O`. Проверять пересечения, исходные0/1, смену запрета, холодный кеш, гибель целей, неизвестные/пустые описания и все6языков.
5. Нативный синтаксис проверять компилятором Lua4. Lua5.1 mock не ловит все ограничения движка. Форматирование Lua должно сохранять токены; fixtures сами по себе не подтверждают поведение в игре.
6. По запросу человека собрать/установить HWMPAutoTests и выполнить адресную очередь. Не пересобирать пакет посреди очереди. Собираются только собственные процессы; чужая игра не останавливается. Здоровый timeout остаётся открытым.
7. При save/load подтвердить свежий собственный checkpoint, откат времени/маркер и OnStartOrLoad, затем настоящее движение. Проверить новый процесс, пересечения, уход за радиус, гибель источников, запрет сценария. Отрицательные и невалидные опыты сохранить, не переименовывать в passes.
8. Быстродействие сравнивать на одинаковой постановке/интервале. Внешнее wall time не равно FPS/CPU. Первый64-bit журнал был функционален, но около3×медленнее; компактный адресный дал отдельные6–9% образцы. Сеть и долгие матчи отдельно.
9. `python tools/hwmp24.py --package` полностью распаковывает каждый основной/языковой BIG и сверяет payload. Допустимы родные алиасы data/locale; colon-qualified aliases запрещены. Сверить fixes.json, checksum list, scope численных изменений. Состав релиза общий у сборщика и установщика.
10. После правки только документов обновлять текст/SHA256SUMS/ZIP без перепаковки BIG. После runtime/перевода пересобрать и повторить подходящие native проверки. Записать конкретную идентичность проверенного пакета.
11. Установка отдельно: install_hwmp24.py безфлага — план, с --install — собственная папка. Штатный слот: launcher_slot.py hwmp --apply; вернуть VR: previous --apply. Полная проверенная копия предыдущего слота вне игры обязательна. Не менять оригинальный BananaDLC и чужие моды.
12. Пройти полевую приёмку: два клиента, штатные/2x старты, языки, корпуса/ремонт, UI-прыжок/отмена/охрана и полные Hgn↔Vgr матчи. Старые активные saves без журнала не гарантируются; кампания и переходы уровней проверяются своим потребителем.
13. Перед push просмотреть staged файлы: только код/документы/переводы/хеши/текстовый архив примеров. Сырые логи, saves, PID, настройки, ассеты и BIG исключить. Push обычный, без force чужой истории.
14. Для Workshop готовить loose data, config, английское описание и отдельное русское, preview512×512<1MiB. Toolkit сам пакует BIG; готовый BIG как его вход не подходит. Title≤128, Description≤8000, WorkshopID0только для нового предмета. Перед create/update показать владельцу описание/картинки и получить решение.
15. После публикации сохранить назначенный WorkshopID, проверить скачанный Steam-пакет через лаунчер и его payload. Не предполагать совпадение бинарного хеша после перепаковки Toolkit. Только затем отдельно обновлять submodule/lock расового слоя и кампании с их собственными проверками.
