# Functional data and descriptive documentation

[Русский](ru/DATA_FORMATS.md)

Markdown explains the current product, procedures and limitations. JSON remains where tools need structured input, pins or receipts. Functional data is not a changelog or a substitute for a user guide.

| Location | Purpose / consumer |
|---|---|
| design/cataclysm.json | Functional ship prices, batches, race membership and budgets; cataclysm.py/verification |
| localization/*.json | Native UI dictionary inputs and coverage generated by language tools |
| baseline/*.json | Pinned source hashes and structured audit inputs; validation/audit tools |
| autotests/manual-cases.ru.json | Explicit Russian operator test data read by native_checks.py; not runtime gameplay |
| workshop/item.json | Workshop identity read by staging |
| workshop/published-release.json | Current structured publication/download receipt |
| workshop/releases/*.json | Historical machine-readable release receipts |
| docs/archive/**/evidence/*.json | Archived structured observations; not current feature documentation |

Cataclysm's obsolete status text, policy prose and per-ship Russian provenance notes were removed from its functional configuration. Provenance is preserved in the archive; current prices are readable in [Markdown](SUPPORT_UNITS_PRICES.md). Native manual test data keeps its original bytes/hash at an explicitly language-labeled tooling path. Its Russian human-readable rendering is [here](ru/NATIVE_TESTS.md); the [English test guide](NATIVE_TESTS.md) covers current use.

Generated release version.json is functional installer identity/checksum metadata. It must not be replaced with prose. Raw native logs, saves, process data and extracted assets remain local and excluded from Git.
