# HWMP 2.4 — испытательные полигоны

Отдельный диагностический пакет на полном подготовленном HWMP. Все файлы игровой основы сохраняются побайтно; добавляются только три Extra Missions, SCAR-измерения, RU/EN-строки и копии штатной миниатюры. Обычный выпуск, установленный HWMP, новые расы и кампания не заменяются. Модели и миниатюры остаются вне Git.

После отдельной установки и явного запуска `HWMP Test Grounds.cmd`: **Extra Missions → HWMP 2.4 — испытательные полигоны**. Английский запуск: `HWMP Test Grounds.cmd -Language English`. CMD ожидает собственный каталог `HomeworldRM/DataWorkshopMODs/HWMPTestGrounds`; подготовка пакета его не создаёт и игру не запускает. Не совмещать с другим модом и не использовать старые сохранения. Команда `-PrintOnly` лишь показывает строку запуска.

## Гравиполя — перекрытие и освобождение

Две раздельные площадки: кушане слева, таиидане справа. На каждой два настоящих гравигенератора в 1000 м друг от друга, дружественный полный отряд хиигарских перехватчиков и вражеский полный отряд корветов внутри пересечения. Самоповреждение генераторов сохранено. Материнский Корабль далеко от площадок, неуязвим и не строит.

Подождать минимум две секунды для исходных отсчётов. Выбрать генераторы нужной пары, включить их штатной кнопкой, поставить отметку клавишей **1**. Выключить первое поле, снова **1**; выключить последнее, снова **1**. Проверить движение/стыковку своих перехватчиков вручную. Повторить противоположный порядок в новой миссии. Проверять вторую расу в отдельном свежем повторе, чтобы не терять окно из-за самоповреждения. **2** уничтожает генераторы B обеих рас через настоящий `SobGroup_TakeDamage(...,1)`; этот вариант выполнять отдельно после активации поля B. **3** повторяет инструкцию. Сохранение/загрузка — отдельный опыт с названием стадии и времени.

Скрипт раз в секунду пишет позиции и разрешения Move/Attack/Dock/Custom. CanDoAbility возвращает разрешение хотя бы одной записи группы; единица не доказывает освобождение каждого корпуса в отряде. Вражеским корветам заранее запрещена атака: после освобождения исходный ноль должен сохраниться; у дружественных перехватчиков флаг атаки не меняется постановкой. Скрипт не вызывает GW_MEM, не подменяет callbacks и не освобождает блокировки сам. Отметка означает действие оператора, а не доказательство, что оба поля включились; это сверять по наблюдению/видео. Матрица: N10/N11, частично N12; прочие типы целей, союзная партия и MP остаются отдельными проверками.

## Штурмовой фрегат — отход перехватчиков

Четыре независимые дорожки слева направо: обычный перехватчик/Neutral, обычный/Evasive, Speed Upgrade/Neutral, Speed Upgrade/Evasive. Полные отряды запрошены через штатный size0, не пересобраны в частные корабли. Технология `InterceptorMAXSPEEDUpgrade1` выдаётся только игроку 2, то есть двум правым дорожкам. HP-модернизация не выдаётся. Фактическое применение науки и видимое число корпусов проверить в движке.

**1** одновременно отдаёт приказ отходить и приказ четырём штурмовым фрегатам вэйгров стрелять. Начальная дистанция центров 1300 м, поперечный интервал 10000 м. Фрегатам запрещено перемещение, целям — атака. Измерение длится 45 игровых секунд, затем новые выстрелы отключаются. **3** повторяет инструкцию. Повтор — новая миссия, минимум три раза на вариант. Скрипт записывает дистанции, здоровье, число записей отряда и скорость его центра по последовательным позициям. Последняя не равна мгновенной скорости каждого аппарата и может меняться от строя/потерь.

Это исходный HWMP с неизменённой скоростной кривой Assault, без A/B-накладок. По разнице потерь нельзя автоматически доказать влияние узла535→4: отличаются строй, скорость и время под огнём. Стенд отделяет четыре комбинации, но не заменяет будущий A/B с одной правкой кривой, преследование N82 или полноценный балансный матч. Основное соответствие: подготовка к N80.

## Тяжёлые ракеты — потеря цели

Неподвижный штатный Heavy Missile Frigate стреляет в пассивный торпедный фрегат на 2200 м. Второй торпедный фрегат в 632 м от первого — возможная замена. Обе цели без атаки/движения. **1** начинает огонь. После визуально подтверждённого пуска тяжёлой ракеты **2** сначала останавливает пусковую и запрещает ей атаку, затем наносит исходной цели100% урона. Подтвердить фактическую гибель по журналу/экрану. Наблюдение продолжается35 секунд. **3** повторяет инструкцию. Контроль: в новой миссии нажать только1; завершение через45 секунд.

Прекращение стрельбы — явное вмешательство, записанное в журнал. Если цель погибла от обычного огня до кнопки2, контроль завершается с `control_invalid`, а не считается опытом с сохранённой целью; повторить в новой миссии. После завершения кнопка2 не действует. Тяжёлые и вспомогательные ракеты фрегата сосуществуют; общий `Selection_GetMissiles`, если API доступен в SCAR, не даёт их типа/индивидуальности. Наличие урона у второй цели само по себе не доказывает перенаведение тяжёлой ракеты. Снять видео, отмечая тяжёлую ракету до/после гибели цели, новые пуски и возможные попадания малых ракет/взрыва. При недоступном Selection API опыт остаётся визуальным, счётчик помечается unavailable. DD/BC, другие типы брони, равное число заменённых ракет N73 ещё не покрыты; стенд — первый частный опыт N71/N72.

## Журнал и границы проверки

Строки начинаются `HWMP_TEST|v=1|suite=<revision>|mission=...|t=...`. Время игровое. Сохранять свежий `HomeworldRM/Bin/Release/HwRM.log` сразу после опыта, до следующего запуска. Для разбора:

```powershell
python tools/collect_testgrounds.py --log "путь\HwRM.log" --output "local\testgrounds\observations.json"
```

Сборщик проверяет ревизию текущего подготовленного пакета, отделяет повторные входы в миссию, сохраняет события/образцы/дистанции и отмечает незавершённые опыты. Его вывод — `observation_only`, происхождение логов не аутентифицируется. Он никогда не переводит N00–N84 или отдельный опыт в passed. Число SobGroup-записей не объявляется числом физических корпусов. После завершения опыта миссия остаётся открытой; автоматической победы/выхода нет. Повторять через меню новой миссией. Нативная работа меню, callbacks, науки, оружия, сохранений и клавиш пока **not_run**.

Сборка: сначала обычный HWMP `tools/hwmp24.py --package` при необходимости, затем `tools/testgrounds.py --package`. Нельзя пересобирать обычный выпуск просто ради полигонов: используется его уже подготовленный источник из manifest.json. Текущие исходники/контейнеры основы защищаются сравнением SHA. `tools/verify_testgrounds.py --luac <Lua4 luac.exe>` проверяет меню/ссылки/RU-EN, компиляцию диагностического кода Lua4 и сценарные mocks; полная распаковка всех трёх BIG включена в сборку. Это не запуск движка. Готовый пакет — `local/HWMPTestGrounds-release`; основной выпуск — по-прежнему `local/HWMPPatch24-release`.

Lua4-компилятор для локальной проверки собран из официального [Lua4.0.1](https://www.lua.org/ftp/) (SHA256 исходного tar.gz `df746e149cf6939e90009d2e540eee918d585b4d1bc6d68b19316a050d484d2a`). Он проверяет синтаксис, но не API Homeworld. Бинарник/исходники инструмента не входят в мод и Git.
